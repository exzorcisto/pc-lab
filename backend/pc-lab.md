# Проект: API платформы «PC Lab» — Конструктор и магазин ПК

## Описание предметной области (Backend)

Backend-часть платформы «PC Lab» представляет собой RESTful API, обеспечивающее работу интернет-магазина комплектующих и интеллектуального конфигуратора системных блоков. Основная сложность серверной части заключается в реализации логики проверки совместимости компонентов (сопоставление сокетов, стандартов ОЗУ и расчет лимитов энергопотребления TDP).

Сервер обрабатывает запросы от React-клиента, управляет каталогом, корзиной, заказами и системой пользовательских сборок.

**Аналоги по функционалу API:** Конфигураторы DNS, Citilink, HyperPC.

---

## Функциональные требования (Backend)

### Управление пользователями и доступом
- Реализация системы аутентификации на базе **Laravel Sanctum**.
- Разграничение прав доступа через Middlewares: **Администратор** (управление каталогом) и **Клиент** (создание сборок, заказы).

### Управление каталогом и характеристиками
- CRUD-операции для категорий и компонентов.
- Хранение и отдача расширенных технических характеристик в формате JSON для динамических фильтров.
- Управление складскими остатками (`is_available`).

### Логика конфигуратора (Бизнес-логика)
- Эндпоинты для фильтрации совместимых комплектующих (например, `GET /api/components?socket=LGA1700`).
- Серверная валидация готовой сборки: проверка связей `socket`, `ram_type` и суммирование `tdp` всех компонентов.
- Генерация уникальных хэшей (`share_hash`) для сохранения и обмена конфигурациями.

### Обработка заказов и отзывов
- Прием заказов с фиксацией цены товара на момент покупки (`price_at_purchase`).
- Смена статусов заказа через Enum: `new`, `processing`, `completed`, `cancelled`.
- Система модерации отзывов и обработки заявок на обратный звонок.

## Чекпоинт 1: Проектирование и инициализация Backend

**Задачи:**

### 1. Инициализация окружения
- Создание проекта Laravel и настройка `.env`.
- Настройка подключения к СУБД MySQL.
- Настройка Git-репозитория и файла `.gitignore`.

### 2. Проектирование БД (на основе файла image_a8bcb8.png)
- Реализация миграций для всех ключевых таблиц:
    - `users`, `categories`, `components`.
    - `build_templates` и `build_template_items`.
    - `saved_builds` и `saved_build_items`.
    - `orders`, `order_items`, `reviews`, `callback_requests`.
- Использование типов **Enum** для статусов и ролей.

### 3. Проектирование API (Маршрутизация)
- Определение структуры эндпоинтов в `routes/api.php`:
    - `GET /api/components` — каталог с фильтрацией.
    - `POST /api/builds/validate` — серверная проверка совместимости.
    - `POST /api/orders` — оформление заказа.
    - `GET /api/categories` — список категорий для навигации.

### 4. Наполнение данными
- Написание **Seeders** и **Factories** для генерации тестового набора комплектующих (процессоры, материнские платы) с корректными связями сокетов для тестирования логики.

**Демонстрация (Результат):**
- Ссылка на GitHub с начальной структурой проекта.
- Сгенерированная ER-диаграмма (соответствующая коду миграций).
- Документация эндпоинтов (Markdown или Swagger).
- Успешный запуск `php artisan migrate:fresh --seed`.

### Чекпоинт 2: Авторизация и управление каталогом (Backend)

**Задачи:**

- **Система доступа:**
  - Реализовать регистрацию и авторизацию на базе **Laravel Sanctum** (Token-based auth).
  - Настроить Middleware для защиты эндпоинтов админки.
- **Управление компонентами (CRUD):**
  - Реализовать API для создания, редактирования и удаления комплектующих.
  - Реализовать загрузку изображений для товаров (хранение в `storage`).
- **Интеллектуальная фильтрация:**
  - Создать эндпоинт `GET /api/components` с поддержкой фильтров: по категории, сокету, типу памяти и диапазону цен.
- **Логика конфигуратора (Первый этап):**
  - Реализовать эндпоинт для получения совместимых деталей (например, выбор материнской платы на основе уже выбранного процессора).
- **Валидация характеристик:**
  - Настройка валидации: например, нельзя сохранить процессор без указания TDP или сокета.
- **Расширенные сидеры:**
  - Наполнить базу данных полным набором комплектующих для одной актуальной платформы (например, LGA1700 + DDR5), чтобы можно было собрать полноценный ПК.

**Демонстрация (через Postman/Thunder Client):**

- **Авторизация:** Регистрация нового пользователя и получение токена.
- **Каталог:** Получение списка видеокарт с фильтром по цене.
- **Конфигуратор:** Запрос на получение всех материнских плат, подходящих к конкретному `socket` выбранного процессора.
- **Админка:** Создание нового компонента через POST-запрос с токеном администратора.
- **Детальный просмотр:** Получение полной информации о товаре, включая вложенный объект категории и массив `specifications`.

### Чекпоинт 3: Корзина, заказы и глубокая валидация

**Задачи:**

- **Система заказов:**
  - Реализовать эндпоинт `POST /api/orders` для оформления покупки (перенос товаров из корзины/сборки в таблицу заказов).
  - Реализовать логику статусов заказа (Новый, Обработан, Отменен).
- **Личный кабинет пользователя:**
  - Эндпоинт `GET /api/user/builds` для просмотра истории всех своих сохраненных конфигураций.
  - Эндпоинт `GET /api/user/orders` для отслеживания статуса своих покупок.
- **Глубокая техническая валидация (Compatibility 2.0):**
  - **Проверка мощности:** Реализовать расчет суммарного энергопотребления (TDP) процессора и видеокарты против мощности выбранного блока питания (БП).
  - **Тип памяти:** Валидация соответствия оперативной памяти (DDR4/DDR5) слотам материнской платы.
  - **Форм-фактор:** Проверка, влезет ли выбранная материнская плата (ATX/mATX) в выбранный корпус.
- **Обратная связь:**
  - Реализовать эндпоинт `POST /api/callback` для формы «Перезвоните мне» или консультации по сборке.

**Демонстрация (через Postman/Thunder Client):**

- **Заказ:** Оформление заказа авторизованным пользователем и получение ID транзакции.
- **Ошибка совместимости:** Попытка сохранить сборку, где мощность БП (например, 450W) меньше суммарного потребления системы (например, 600W) — получение ошибки 422.
- **История:** Получение списка всех сборок, созданных конкретным пользователем.
- **Валидатор:** Успешная проверка совместимости DDR5 памяти с соответствующей материнской платой.
